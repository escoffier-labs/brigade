- Stop `brigade init`, `brigade reconfigure` and `--force` from overwriting an installed `SKILL.md`. Init writes only a missing one. A copy that differs from the bundled template is kept and the new text is filed once per destination as a skills inbox proposal, labelled `edited` or `pristine-stale`, with a stable `brigade://bundled-skills/<id>@<version>` source. A symlinked, junctioned or FIFO `SKILL.md` or parent directory is left alone with no proposal. The destination is walked and created through a held directory descriptor, so a parent swapped mid-run cannot redirect the write. A CRLF copy compares equal to the LF template.
- Add an optional `dedupe_key` and `provenance` to `inbox_add` so a repeated filing returns the existing proposal id with its original exit code instead of a duplicate. Record each `SKILL.md` init writes in `.brigade/skills/wired.json` under the skills mutation lock, keeping a copy of an unreadable file instead of dropping its records.
- `brigade reconfigure --prune` now warns about each `SKILL.md` under a pruned harness directory that differs from the bundled text.
- Publish a new `SKILL.md` atomically (fsynced temp sibling, then a no-replace move under the held descriptor), so a failed or interrupted write leaves no file rather than a truncated one that later runs keep as `edited`. A permission, read-only-disk or I/O error on one skill is now a kept outcome with a warning naming the path and errno; the other skills, the `wired.json` records and the rest of init still run. `brigade doctor` points a kept `stale skill` at `brigade skills inbox list` when init filed a proposal for it.
