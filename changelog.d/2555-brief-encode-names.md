- `brigade work brief` sends every value it prints that came from the filesystem, from Git, from configuration or from ingested content through the encoder the instruction-budget lines use: only ASCII letters, digits and `. _ - / ~` pass, every other character is written as an escape, the length is capped with a visible `[truncated]` mark, and the line keeps its fixed prefix. A plain path or identifier still prints unchanged.
- Every printed line of the text brief also passes one sanitizer on its way to the stream. A line break, a NEL, a line or paragraph separator, any other C0 or C1 control, an ANSI escape, a bidi override and a zero-width character is escaped wherever it appears, so no value can start a new line or hide text even at a site nobody encoded. JSON output is unchanged.
- Covered surfaces: dirty and untracked `git status` entries (the status code is git's own and prints as is), the branch, session paths, titles, notes and handoff paths, dogfood run fields and next-task text, task and import text with their ids, sources and kinds, hub overlap rows, cloud stale rows, health row details, section exception details, scanner, sweep, review, care, backup, daily, phase, tool, roadmap, repo-fleet, context, project, learning, research, operator, handoff and recent-session rows, the pantry role, peer and last sync, the notifications status, the `fleet_routing` block and the outcome-ratchet line.
- A suggested command with a task text that is not plain enough to survive shell quoting is printed as `withheld (unsafe characters; see --json)` instead of an escaped command that cannot be pasted, and an operator or research command from a record is withheld when its own text holds a shell metacharacter. The JSON payload still carries the real command.
- The `work_mode_pin` line keeps its fixed prefix readable and encodes only the exception after it. Values Brigade composes itself (counts, fixed statuses, commands with no untrusted argument) stay readable, and so does the default review text the brief writes itself.
