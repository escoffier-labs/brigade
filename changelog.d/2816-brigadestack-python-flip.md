- Publish the Python package as `brigadestack`. `pipx install brigadestack` and `uvx brigadestack` install the same `brigade` CLI, Python imports, and storage formats as before. `brigade-cli` stays on PyPI under the old name (#2816).
- `brigade update` installs `brigadestack` on both channels and resolves daily beta wheels from the `brigadestack` project, which is the only name that publishes them. On a `brigade-cli` pipx app it installs `brigadestack`, removes the old app, installs `brigadestack` again to restore launchers older pipx removes by name, runs setup from the `brigadestack` environment, and only then records the update. That environment is located by asking pipx (`pipx environment --value PIPX_LOCAL_VENVS`, absolute paths only, then `PIPX_HOME/venvs`), never from the `PIPX_LOCAL_VENVS` variable that pipx ignores, and it is used only when its `pipx_metadata.json` names `brigadestack`. If the removal fails, or on Windows where retiring the old app waits until after exit, the update exits non-zero without recording and prints the commands to finish. If the second install fails, the launchers are relinked to the existing `brigadestack` environment without the network and nothing is recorded. Outside pipx, an install with both a `brigadestack` and a leftover `brigade-cli` distribution counts as `brigadestack` (#2816).
- Count `brigadestack` and `brigade-cli` PyPI downloads together in the downloads badge, with a per-package breakdown in the metric JSON (#2816).
- The MCP Registry manifests launch `brigadestack`, the version check sends a `brigadestack/<version>` User-Agent, and install hints, the Dockerfile and the install docs name `brigadestack` (#2816).
