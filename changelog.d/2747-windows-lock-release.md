- Release a Windows `tasks.json.lock` or `run.lock` while a waiter holds its `pid` or `owner.json` open: the release now unlinks those names with POSIX-semantics delete, under the stale-recovery gate, and only then renames the directory, so a contended release no longer raises `PermissionError` and strands a live owner's lock. A volume without that support keeps the previous rename-only behaviour, and a release that still gives up puts its metadata back.
- Read lock metadata with delete sharing on Windows in every reader, including `owner.json` and the patrol lane reader, wait out a name whose delete is still pending instead of failing, retry a denied release with a backoff that starts near 1 ms, and read the owner metadata once per stale check instead of twice.
- Keep releasing by the published directory's identity when `owner.json` is lost or corrupt, and keep a reserved worktree's lease directory empty so its owner can still remove it.
