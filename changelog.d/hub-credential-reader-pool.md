- Keep fleet hub credential lookups on their own pool, sized like the handler pool (`hub_threads()` readers, 2 to 8, and the same 1,024-job queue), so a slow status or claims read no longer holds the 2 s credential deadline and answers `503 {"error":"hub busy","reason":"credential-lookup"}` without making authentication a smaller choke point than it was on main.
- Route every native route's own token check to that pool too: the `claims`, `heartbeat`, `messages` and `registration` handlers and the memory route's `Store::authenticate`. Only real data reads stay on the handler pool, so the second read no longer answers `credential-lookup` while a handler read is slow.
- Give the hub at least two handler readers on a single-CPU machine, and count a handler or credential read job's 2 s deadline from when it was queued rather than when a reader starts it, so no caller waits out a queue wait and then a run window it will not read. The memory pool keeps its own policy: its run budget counts from when a reader starts, so a search that queued for most of its limit still gets a full run window.
- Name the request log's `credential_kind` from the same lookup that authenticates the request. `anonymous` means the request presented no bearer token, or its lookup completed without a live row, so an unknown or revoked token reads as `anonymous` as it did on main; `unchecked` covers a presented token no lookup completed for, such as one refused before the lookup or one whose lookup timed out.
- Add a `pool` label of `handler`, `lookup` or `memory` to `brigade_hub_reader_jobs_total`, `brigade_hub_reader_queue_wait_seconds_total`, `brigade_hub_reader_run_seconds_total` and `brigade_hub_reader_timeouts_total`, count a full queue's refusal as `reason="queue-full"`, and keep `brigade_hub_reader_queue_depth` reporting the handler and memory pools as before.
