- `brigade mcp sync` no longer blocks a Claude Code server with `native_auth_source_collision` when its only catalog auth reached the catalog from Codex (`bearer_token_env_var`, `http_headers`, `env_http_headers`). When the live `claude` or `claude-user` entry carries a `headersHelper`, that helper is the auth for the harness: the sync leaves the Codex-native fields out of the Claude entry, keeps the helper, writes the entry and reports it `current`, so a second sync is a no-op. Each dropped field is reported as `native_auth_helper_precedence` (field name only, not blocking) in the plan, sync and fidelity output. Catalog `headers` next to a live helper, including next to a Codex-native field, are still blocked with `native_auth_source_collision`, and `--force` and `--adopt` still do not override it. Origin, transport and removal blocks are unchanged, entries without a helper project exactly as before, and Codex entries keep their own auth.
