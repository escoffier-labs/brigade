- Add `brigade outcome reconcile --proposals`, which files one skills inbox proposal for each `regression_hold` or `regression_rollback` on a Brigade-bundled skill. The proposal stages the current skill text unchanged, is marked `requires_revision`, and carries a behavioral contract built only from the observed artifact, reason code, receipt run ids and the failing check ids and commands read back from those receipts. A gone receipt reads `command unavailable`. Only a copy whose own install receipt is a reviewed Brigade bundle, and whose files still match that receipt, is staged. Registry skills are reported as `flagged`, a skill installed from different sources in different harnesses as `flagged: mixed-source`, a hand-edited bundled copy as `flagged: local-edit`, and path skills or a copy the receipt cannot vouch for as `skipped`; observed regression holds file nothing yet.
- Make that filing idempotent through an `outcome:<artifact_id>:<fingerprint>` dedupe key, so a repeat run reports `existing`, and a rejected proposal stays muted, for a later rollback of the same text as well, until the skill text changes. A failure warns and never changes reconcile's exit code, and a dry run files only when `--proposals` is passed and says so.
- Refuse `brigade skills inbox accept` for a `requires_revision` proposal whose files still match the unrevised text it was filed with, or that lacks that record (exit 2, `--force` included), because accepting it would change nothing and still mute the dedupe key. Re-filing the same unrevised files under a different behavioral contract is refused at `inbox add` and again at accept.
- Store the filed, existing, flagged and skipped counts in the ratchet report and show them in `brigade outcome ratchet`, as a new `outcome_proposals:` line in `brigade work brief` and in the dashboard ratchet panel. The weekly outcome ratchet runbook now passes `--proposals`.
