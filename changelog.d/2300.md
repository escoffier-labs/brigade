- `brigade memory hub status|pull|push|import|card` reads and publishes hub memory on a Rust hub. A `[hub]` table in `.brigade/memory-care.toml` sets the mode (`off` by default, `read`, `sync`) and the publish scope (S14).
- In `read` and `sync` mode, `memory search` fuses hub and local matches, labels where each came from, and falls back to local cards and the per-host replica when the hub is unavailable. `off` mode output is unchanged.
- Writes the hub cannot take right now are spooled and replayed with the same `client_event_id`. A conflicting offline edit becomes a local proposal instead of overwriting the hub. A spooled write replays only onto the same readable, public card at the same path; a card that turned private, was renamed, moved, re-identified, duplicated, deleted or made unreadable keeps the write as a local proposal that is never sent. Dot and Duet memory tools follow the same mode.
- Hub memory reads stay inside the workspace's read scopes: `[hub] read_scopes`, which defaults to `[scope]`, limits every hub search, card read and the replica, so Dot and Duet can no longer read other scopes the credential can read. The client uses only the node token and never falls back to the admin token.
- The replica belongs to the principal the hub's `status` names, which now reports `principal`, `credential` and, for a `scopes` list, `readable_scopes`. A different principal rebuilds the replica, and a scope that is no longer readable is dropped at the next pull.
- A refused hub search (401, 403 or another coded answer) answers from local cards only and never from the replica. Redirects, 408 and 429 count as unavailable, so writes spool instead of becoming proposals, and a 401 at the push preflight spools too. A write-only credential can push.
- `memory hub proposals list|drop` lists open proposals and closes one after review. `drop` needs `--keep-local` (the next push writes the local card over the hub head) or `--keep-hub` (the local card file takes the hub head), and refuses unless the replica is current for this hub, principal and `log_epoch` and holds the card head the hub's `card` answers now, so a replica pulled before the conflicting write is refused. `--keep-hub` finds the local card by id, rewrites a moved card where it is, and refuses when the card file is not UTF-8. Both refuse when two files hold the id or the proposal's scope is not the current `[hub] scope`, and `--keep-local` says when the next push sends nothing. A dropped or resolved proposal moves to `.brigade/memory/hub/proposals/dropped/` with its text. A proposal also resolves on its own when the local card takes the hub head the conflict reported and the replica agrees. Spool entries for another hub no longer block cards or count against the cap.
- `push` and proposal changes hold a lock on the workspace's hub state, which now lives in its own `.brigade/memory/hub/` directory. `pull` holds its own lock and takes the state lock only while it changes the replica, so a long pull no longer blocks a push, and a run that waits too long for a lock exits 75 saying another push or pull is running. Pulls check the epoch on every card answer and again before saving, write `heads.json` a few times per rebuild instead of once per page, and fetch cards left out for the cap once space frees.
- Dot and Duet `memory_card` take an optional `scope`, so a card held in two read scopes can be opened. Search reports the hub's `match_count`, warns when `--limit` exceeds the hub's 20, and keeps the same bytes in two scopes apart.
- `status`, `pull`, `push`, `import`, `card` and `proposals drop` refuse when the hub reports that the node-token slot holds its admin token, so Dot and Duet `memory_card` refuse it too. Search makes no `status` call and cannot tell. `memory hub card --all` refuses to join chunks from two `log_epoch`s or text that does not match the card's `content_hash`, and while the hub is unavailable `memory hub card` and Dot and Duet `memory_card` read the card from the replica, never from a read scope the hub refused the card in during that read, and not at all after a `status` 403 or a `log_epoch` move during the read.
