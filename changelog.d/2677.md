- `brigade skills doctor`, `brigade skills fleet status`, `brigade skills sync`, and `brigade skills diff` no longer raise when an installed skill directory is a symlink (including one that points outside the workspace), a dangling link, or a regular file; the copy is reported with a `symlink` (or `unusable`) state, the link target is shown, and the rest of the report completes. A missing `.brigade/` state root still reads as `missing`, not `unusable`. The fleet report sent to the Hub keeps its existing statuses: `symlink` is sent as `external` and `unusable` as `unknown`.
- `brigade skills sync --write`, `install`, `uninstall`, and `rollback` leave a non-plain installed skill copy untouched and say it was skipped and why, re-checking the path right before every write so a link planted after the first check is never followed. `install` reports `installed: false` when every target was skipped, and exits non-zero when one explicit `--harness` is skipped without `--force`; `--harness all` skips that harness and continues. Registry and source-side symlink refusal is unchanged.
