- `brigade skills doctor`, `brigade skills fleet status`, and `brigade skills sync` no longer raise when an installed skill directory is a symlink, a dangling link, or a regular file; the copy is reported with a `symlink` (or `unusable`) state, the link target is shown, and the rest of the report completes.
- `brigade skills sync --write`, `install`, `uninstall`, and `rollback` leave a non-plain installed skill copy untouched and say it was skipped and why. Registry and source-side symlink refusal is unchanged.
