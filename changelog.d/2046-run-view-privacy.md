- `brigade runs list --json` and `brigade runs show --json` are now the `brigade.runs-list.v2` and `brigade.run-detail.v2` contracts. `task` is a keyed digest object rather than a bounded string, so a v1 reader must check the schema name. `brigade.run-watch.v2` covers the watch records.
- Served run views now keep only closed values readable. Enums, ISO timestamps, hex ids, run ids and fixed tokens stay, and every other string becomes a per-host keyed digest, including roster agent names and mapping keys, agent model and reasoning, worker names, requested models, failure kind and class, and non-home paths such as `/etc/ssl/private/key.pem`.
- A refused or unusable digest key now fails closed: CLI JSON exits 3 with `error: run digest key unavailable`, the Run View JSON endpoints return 503 with a fixed body, and the watch stream sends one closed error record. Unreadable runs return a fixed 502 body and a closed `run-unreadable` header instead of a path.
- The Center Runs dashboard renders a task digest object as `digest <hex> (N chars)` instead of a mapping repr.
- A user-chosen `--output-dir` name is never echoed. Only Brigade-generated run ids stay readable, and a custom name becomes a keyed digest in list/show JSON, the served list, detail, SSE, event ids and the handoff note. The Run View resolves the digest back to the run server-side, and a raw custom id in a route is refused.
- The Run View now formats every projected object and digested mapping key with the short digest label, keeps worker status and synthesis mode readable, and no longer renders an empty roster assignment or result column.
- The Brigade run memory handoff note records the run id, status, mode, counts, timestamps and keyed task digest only. Task text, assignment text, worker detail, generated text, cwd and absolute paths no longer enter the memory inbox.
