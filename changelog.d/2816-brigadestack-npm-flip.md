- Publish the npm package as `brigadestack`. `npm install -g brigadestack` and `npx brigadestack` install the same CLI as before and provide both the `brigade` and `brigadestack` commands. `@escoffier-labs/brigade` stays on npm as a compatibility package that depends on exactly `brigadestack@<same version>` and declares its own `brigade` command, so `npm update -g @escoffier-labs/brigade` keeps a working `brigade`. `npm-publish.yml` publishes the compatibility package last, after native registry acceptance of `brigadestack`, and the one-time `brigadestack-npm-publish.yml` bridge workflow is retired (#2816).
- The npm launcher names its private uv tool directory after the bundled wheel (`tools/brigadestack`) and accepts only `brigadestack` and the legacy `brigade-cli`. Payload roots are keyed by the wheel's SHA-256, so an upgrade from an older npm install provisions a fresh root and never reads, follows links in, rewrites or deletes the old `tools/brigade-cli` tree (#2816).
- The plugin MCP configs launch `npx -y brigadestack@<version>`, and the downloads badge counts `brigadestack` and `@escoffier-labs/brigade` npm downloads together, with a per-package breakdown (#2816).
