- Run each explicit batch task that declares `isolation: "worktree"` in its own reserved checkout. Before any worker is submitted, execution checks the pinned base, then either replays a recorded binding or reserves, creates, validates and records one `task.workspace-bound` fact per task; a task whose journal already shows an attempt gets no checkout. The checkout is validated again immediately before launch, and the worker process runs there while cassettes, receipts, the task journal, the run budget and caller run-lock resolution stay on the caller workspace (#2050).
- Refuse the whole batch with `source-changed` when the caller workspace no longer matches the pinned base at execution, and with `isolation-remote-unsupported` when worktree tasks would route through Fleet Hub to another machine. Both refuse before any launch.
- A per-task workspace refusal reports its closed code and refuses only that task, never deleting anything. Each task checkout holds its own run lock from creation through worker exit so `brigade runs prune-worktrees` skips it, and task checkouts and branches are kept after every outcome.
- Batch result JSON task entries gain `workspace`, `worktree` for a task that ran in its own checkout and `shared` for one that ran in the caller workspace.
