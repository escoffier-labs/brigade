- A Compose install of the Fleet Hub now reaches hybrid retrieval when setup picks it. `brigade fleet serve --engine rust` takes `--memory-config PATH` and passes it to `brigade-hub`, and `ops/fleet-hub/compose.yaml` names the `config/hub.toml` that `bin/hub-setup.py` writes. The hub logs one line at startup naming the memory configuration file it read and the retrieval mode. An image built from a `BRIGADE_REF` older than the flag keeps starting: `hub/entry.py` drops the flag with a warning and that hub runs in BM25 mode.
- The hub container's entrypoint copies the mounted embedder token to `/run/brigade/embed_token`, owned by the hub's user with mode 0400, on a tmpfs private to the container, and refuses a symlink at the mount. The hub accepts an embedder token only from such a file, and a bind mount keeps the operator's ownership. Setup writes that path into `hub.toml`, writes both embedder token files with mode 0444 inside the 0700 `secrets/` directory so the container can read them, and resets a local token an earlier setup wrote with mode 0400.
- For the `api/embed` request shape, a reply that carries no model digest is now checked against the server's model listing at `/api/tags` on the same origin. The hub compares the listed digest with the pinned `model_digest` and refuses replies with `digest-mismatch` once a reading shows another digest or cannot vouch for the model. A document batch and the breaker's probe read the listing before the request and again after the reply, inside the call's deadline, and the vectors are kept only when both readings report the pinned digest. A query takes one reading and reuses it for up to 30 s. A reply that carries a digest is decided by that digest alone. Before this, the hub refused every embedding from a local server that sends no digest.
