- Add `brigade-hub memory-restore-epoch --memory-db <file>`, which starts a new memory `log_epoch` on a `fleet-hub-memory.db` restored from a copy, before the hub serves it. Clients then rebuild their replicas on the next pull, and a write based on a revision from before the restore is refused with `409 memory_epoch_changed` instead of overwriting a reissued revision. The command refuses, changing nothing, while a process holds the file, when a stale `-wal` or `-journal` sits beside it, for a file that is not a memory file or has a newer schema, and when SQLite's `quick_check` fails. The dogfood runbook's restore steps now cover the memory file.
