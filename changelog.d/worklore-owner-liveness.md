- Distinguish a live owner, an idle owner with unfinished work, an expired observation, and a confirmed terminal execution in Worklore ownership reads, with the derived liveness state computed on read and never stored.
- Add `liveness_basis` and `liveness_freshness` to the ownership read, using only fixed state, basis, and freshness words and never a claim target, session id, process id, path, or another node's capability.
- Derive prepared handoff report freshness as `recent`, `stale`, `future`, or `unknown`. An older reader that accepts only `unknown` and `unassessed` refuses the new values and fails closed. A newer reader still accepts an older Hub's `unassessed`, but an older CLI cannot read a newer Hub's prepared handoff, so upgrade the Hub and the CLI together.
- Scope every liveness fact to the item: sessions and claims count only for the snapshot's repository identity, and a linked run counts only for the current owner in the current ownership generation. A lapsed lease now wins over a live session or claim.
