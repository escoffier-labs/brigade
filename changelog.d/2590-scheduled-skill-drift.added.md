- Add `brigade skills fleet drift [--report]`, a read-only drift check for installed skill copies that needs no manual `skills fleet status` run. It classifies each copy as `current`, `refreshable` or `flagged`. A copy byte-identical to a text a past release shipped, and a receipt-known stale bundled copy whose receipt proves it was never edited and whose `SKILL.md` is a recorded release text, is listed as `refreshable` with the exact `skills install` command to run. Every other drifted, edited, unknown, receiptless or linked copy (a symlink, or a `SKILL.md` with more than one hard link) is flagged. The step never writes a skill copy. Links, a missing copy and every copy outside the workspace, Hermes included, are reported or skipped, and report paths are normalized workspace-relative POSIX paths. It reuses `skills fleet status` and the shipped-release history from the pristine refresh, so there is no second comparator.
- Run it weekly as a new `skill-drift` step at the end of the `weekly-outcome-ratchet` runbook. The weekly job flags and lists refreshable copies but never writes them. Unattended refresh is deferred because a workspace receipt cannot authorize a write, and refresh stays with `brigade init` and `brigade skills install`. `brigade care install` refreshes an untouched copy of the earlier runbook, and a customized one is kept and reported as drifted.
- Write the result into `ratchet-report.json` under `skill_drift` with the current, refreshable, flagged and skipped counts and the bounded flagged and refreshable rows. `brigade work brief` prints it as a `skill_drift:` line next to `outcome_ratchet:`, the dashboard outcomes panel shows it, and `brigade outcome ratchet` prints it. A row whose path is not a normalized workspace-relative POSIX path is dropped on read and never rendered. A later `reconcile --report` keeps the last drift block, the block counts against the report size cap, and a report that cannot be read is never replaced. Refs #2590.
