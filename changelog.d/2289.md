- A busy stale-recovery gate no longer makes a dead run-lock owner look active: `brigade runs recover` and run acquisition wait up to two seconds for the other recoverer, then report "stale lock recovery in progress". A recovery gate that cannot be opened or locked now fails with an error that names the gate file and how to clear it.
- When stale-lock recovery gives up on a busy gate, the "stale lock recovery in progress" message now names the recovery gate file and says the gate may be held by a stopped process or may never lock (for example on a share without byte-range locks), with how to clear each. `brigade runs recover` no longer reports a dead run's owner as still active when another recoverer took over the lock for a different run during the wait.
