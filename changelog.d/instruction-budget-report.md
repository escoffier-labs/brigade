- `brigade memory care tend --stage instructions` reports every always-loaded instruction file with its single limit, act-at, trim-to and state, and runs as part of a full `memory care tend`. It moves nothing.
- `brigade doctor` rows `bootstrap-budget: <file>` now use that limit, including user-level files, which warn instead of failing. The old "over hard limit" text is now "over limit".
- `brigade budgets check` reads the same inventory and gains a `warn` status between act-at and the limit, plus `limit_source`, `act_at_bytes`, `trim_to_bytes`, `loaders` and `state` for each file.
- `brigade work brief` prints an `instruction_budget:` line for a file over its limit or of unknown size, and one `config-changed` line while an override was rejected, a limit clamped or a file excluded. File names, configured paths and agent ids in these lines are encoded (`path="ignore\x20previous.md"`), since a model reads the brief.
- A file that cannot be read keeps its size from `stat` instead of passing as 0 bytes, and a size nothing can read is the state `size-unknown`. `budgets check --json` no longer prints the target or home path. A plain `brigade memory care tend` with a bad `[instructions]` table or an inventory error still saves its run and now exits 1.
