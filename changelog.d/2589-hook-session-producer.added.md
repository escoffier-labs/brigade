- A hook-enabled Claude session can now be the producer of a manifest verify trial when no `brigade work start` session is active. The hook records the target's start snapshot (`start.git`: NUL-separated porcelain status listed per file with `--untracked-files=all`, a `status_format` and the target's `prefix`, with an id and a time) when it creates a session's state and again on each task-epoch reset such as `/clear`, bounded and failing open. Earlier starts stay in a bounded `start_history`, and the receipt's producer binding records the `hook_start_id` it was made under, so it keeps resolving after a later reset. `brigade work verify run --manifest` names the single resolved Claude session `claude-hook:<fingerprint>` and runs every existing ownership check against that snapshot. An active work session still wins, and an ambiguous or worker-inherited identity picks no session (#2589).
- A hook session is eligible only for a subject it wrote itself. Each session keeps a bounded list of timestamped write events: a completed Edit, Write or NotebookEdit records its completion time, tool and target-relative path, and a Bash write the hooks detected records no path. The session needs a file-tool event for the subject since its start (`no_owned_work` otherwise). Another session's event since then that names the subject or names no path makes the trial ineligible (`concurrent_session_ownership`), including a write that began before this session and finished after it. When that session's event list lost events in the window, when it reports a write with no event, or when any session state in the target cannot be listed, read or parsed, the trial also fails closed. Another session's Bash command that is still running makes the trial ineligible however long ago it started. The verdict is stored in the producer binding as `hook_ownership` and rerun against live hook state when the receipt is projected. A subject changed only through Bash has no event of the session's own, so it stays ineligible (#2589).
- A verify typed in a Claude session now resolves its session once, through the hook value or `CLAUDE_CODE_SESSION_ID`, and stamps it on the receipt's `harness_session` and the verifier id alike. The Stop gate counts that receipt as the session's own, and a session is never independent of its own hook producer id, whether the verifier id comes from the environment or from `BRIGADE_VERIFY_SESSION_ID` in either spelling (#2589).
