- Read-only Antigravity seats now start as `agy --sandbox --mode plan --print`, so a researcher or reviewer seat can no longer write files through agy's edit tools (`--sandbox` restricts the terminal only). `brigade run` reads the resolved seat's `agy --help` and adds `--mode plan` only when the build lists it, so older agy builds keep the previous argv. On such a build `brigade run` prints one stderr warning that the seat is read-only by prompt only and that upgrading agy fixes it. A failed or timed-out `agy --help` probe is never cached as "unsupported", so a transient failure no longer pins a capable agy to the older argv. Write seats are unchanged.
- Antigravity skills, commands and superpowers are now projected under `.agents/` (`.agents/skills/<id>`, `.agents/commands/`, `.agents/superpowers/`), the workspace root agy discovers, instead of `.antigravity/`. `brigade init` and `brigade reconfigure` remove the Brigade-owned copies at the old paths only after the replacement exists. A legacy `SKILL.md` goes when this run placed `.agents/skills/<id>/SKILL.md` and the file still matches a text Brigade wrote or shipped. A legacy command or superpowers projection goes when the same-named managed projection exists under `.agents/` and its body still matches the recorded fingerprint. Edited or user-authored files, symlinks, Windows junctions and anything below them, and `.antigravity/memory-handoffs` are left alone, and `--no-wire` removes nothing. Only directories a removal emptied are deleted, so an empty directory you created stays.
- A persisted `.brigade/tools.toml` that still maps `antigravity` to the old `.antigravity/commands/` or `.antigravity/superpowers/` default now moves to the `.agents/` path on `brigade init` and `brigade reconfigure`. A path you customized is left as it is.
- The managed gitignore block now ignores `.agents/commands/` and `.agents/superpowers/`, and keeps ignoring `.antigravity/commands/` and `.antigravity/superpowers/` for one more release while old checkouts still hold copies. It leaves `.agents/skills/` tracked, because other harnesses read that directory and teams commit skills to it.
- A bare `gemini-<version>-<family>` model pin on an Antigravity seat, such as `gemini-4-hydrogen` or `gemini-4-neon`, now gets the default `-low` effort suffix, because agy lists Gemini models only as effort-suffixed slugs. Ids that already end in `-low`, `-medium`, `-high`, `-xhigh` or `-max`, hyphenated families such as `gemini-3.8-flash-lite`, and non-Gemini ids, are unchanged.
