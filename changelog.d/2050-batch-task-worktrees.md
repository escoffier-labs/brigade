- `brigade.run_batch_workspace` reserves, creates and validates one per-task checkout for a batch task that declares `isolation: "worktree"`. Paths are recomputed from the repository, run ID and task ID under the worktree cache, a reservation is exclusive, and validation re-checks the path, device/inode, Git toplevel and common directory, branch, `HEAD`, and a pristine status that includes ignored files. Refusals use the closed codes `workspace-overlap`, `workspace-exists`, `workspace-invalid`, and `workspace-unavailable` and never delete anything.
- Batch journals gain the digest-only `task.workspace-bound` fact at run event schema version 3. Only that event uses version 3, so older binaries refuse only journals from a batch that isolated a task and keep reading every other journal.
- A workspace binding never grants launch authority. The bound task stays queued and attempt-free, an identical replay writes nothing, and a different binding for the same task is refused.
- Batch worktree isolation is still refused before launch with `isolation-worktree-not-implemented`; wiring the reserved workspaces into execution is a following slice.
