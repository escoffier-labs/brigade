- Resume `brigade run cloud land` when the private runtime workspace under `XDG_RUNTIME_DIR` is gone, as happens after a logout or reboot: a published landing allocates a fresh workspace, confirms the remote landing branch still points at the recorded commit, and creates the PR through the existing recovery path.
- Refuse the resumed landing with `landing-ref-missing` when the remote branch is gone and `landing-ref-mismatch` when it moved, so a cleared workspace never republishes different content. An existing workspace that fails the safety check is still refused with `unsafe-git-config`.
- Never rebuild or re-push a landing that reached `branch-pushed` or `pr-created`. A missing remote branch refuses `landing-ref-missing` with the exact `git push` command that restores the recorded commit and the `brigade run cloud land` command that resumes, a fetched commit is verified in `FETCH_HEAD` before the local branch ref is created, and a failed resume removes its fresh workspace instead of recording it.
- Adopt only an open or merged PR whose head branch and head commit match the landing, record a merged one as the landing, create a new PR when only a closed one exists, and refuse an open PR at another commit with `pr-recovery-conflict`.
