- `brigade mcp import` followed by `brigade mcp sync --write` no longer strips auth from remote MCP servers. A Claude Code `headersHelper` is kept on the same live entry (it is never copied into the catalog or the ownership sidecar), and `import --merge` now copies Codex `bearer_token_env_var` and header settings into an existing catalog entry for the same server name and exact URL when that entry has no header or auth setting of its own, reporting it as `native_auth_merged`. The kept helper is bound to its URL origin and the check fails closed: a URL with userinfo, a backslash, whitespace, a percent-encoded or non-ASCII host, or a bad port has no origin and never matches. If the catalog moves a server to a different origin or to stdio, sync blocks that server (`native_auth_origin_changed` or `native_auth_transport_changed`), and it also blocks a server whose catalog entry supplies headers next to a live helper (`native_auth_source_collision`); nothing is written for a blocked server and `--force` and `--adopt` do not override it. An install that an earlier sync already stripped has to restore the `headersHelper` or `bearer_token_env_var` line from a backup of its Claude or Codex config; Brigade cannot recover a value it never stored.
