- `brigade mcp import` followed by `brigade mcp sync --write` no longer strips auth from remote MCP servers. A Claude Code `headersHelper` is kept on the same live entry (it is never copied into the catalog or the ownership sidecar), and `import --merge` now copies Codex `bearer_token_env_var` and header settings into an existing catalog entry for the same server name and exact URL when that entry has no auth of its own, reporting it as `native_auth_merged`. If the catalog moves a server to a different origin or to stdio, sync blocks that server (`native_auth_origin_changed` or `native_auth_transport_changed`) and writes nothing for it; `--force` and `--adopt` do not override this. An install that an earlier sync already stripped has to restore the `headersHelper` or `bearer_token_env_var` line from a backup of its Claude or Codex config; Brigade cannot recover a value it never stored.
