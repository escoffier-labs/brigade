- `brigade mcp import` followed by `brigade mcp sync --write` no longer strips auth from remote MCP servers. A Claude Code `headersHelper` is kept on the same live entry (it is never copied into the catalog or the ownership sidecar), and `import --merge` now copies Codex `bearer_token_env_var` and header settings into an existing catalog entry for the same server name and exact URL when that entry has no header or auth setting of its own, reporting it as `native_auth_merged`. The kept helper is bound to its URL origin and the check fails closed: a URL with userinfo, a backslash, whitespace, a percent-encoded or non-ASCII host, or a bad port has no origin and never matches. If the catalog moves a server to a different origin or to stdio, sync blocks that server (`native_auth_origin_changed` or `native_auth_transport_changed`), and it also blocks a server whose catalog entry supplies headers next to a live helper (`native_auth_source_collision`); nothing is written for a blocked server and `--force` and `--adopt` do not override it. A kept helper also stops a removal: `brigade mcp sync --prune`, a harness profile catalog removal and a harness profile uninstall leave an entry that carries a `headersHelper` in place and report that server as `native_auth_blocks_removal` (value-free, naming the server and harness); the rest of the run completes, a blocked profile run exits 1 with status `incomplete` and keeps its ownership record, and the operator removes the helper line or the entry by hand. An install that an earlier sync already stripped has to restore the `headersHelper` or `bearer_token_env_var` line from a backup of its Claude or Codex config; Brigade cannot recover a value it never stored.
