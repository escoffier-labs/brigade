- `brigade ingest` records an unreadable, unarchivable, non-UTF-8 or structurally malformed handoff as a failure, leaves it in place and ingests the rest of the batch. The report adds a `Failed` count, a `PARTIAL` line and `Status partial`, and `brigade repos ingest` carries the failed count and status. `PARTIAL` joins the default ingestor warning patterns. Guard and invariant failures still stop the run.
- `brigade ingest` action lines and the `reason:` line of review drafts now carry a stable reason code (for example `[unsafe-card-name]`, `[near-match-proposal]  match=memory/cards/x.md similarity=0.91`) and a safely encoded handoff filename. They no longer quote target cards, target documents, handoff text, scan excerpts or exception text. Review draft filenames replace characters outside `A-Za-z0-9._-` with `_`.
- `brigade ingest` also reads the handoff inboxes of linked git worktrees of each watched root. Worktrees come from `git worktree list` (output capped at 1 MiB and 256 records) and must share the root's common git dir. Each inbox component is opened without following links. A handoff whose content was already handled in the same run is archived as a duplicate, so one handoff copied into several worktrees ingests once.
- Removing a worktree through Brigade (run cleanup, `brigade runs prune-worktrees`, model trials) first moves its pending handoffs into the main checkout's inbox, deduplicated by sha256. The destination must be the verified main checkout of the same repository. Each copy is written under a temp name the ingesters ignore, fsynced, verified and published without replacing an existing file. The source is removed only if it is still the file that was copied. If any handoff cannot be delivered, or git tracking cannot be established, the worktree is kept and a warning names it.
- In a linked worktree, the Stop hook now asks for the handoff in the main checkout's `.claude/memory-handoffs/`, which survives the worktree's deletion.
