- `brigade ingest` records an unreadable, unarchivable, non-UTF-8 or structurally malformed handoff as a failure, leaves it in place and ingests the rest of the batch. The report adds a `Failed` count, a `PARTIAL` line and `Status partial`, and `brigade repos ingest` carries the failed count and status. `PARTIAL` joins the default ingestor warning patterns. Guard and invariant failures still stop the run.
- `brigade ingest` action lines and the `reason:` line of review drafts now carry a stable reason code (for example `[unsafe-card-name]`, `[near-match-proposal]  match=memory/cards/x.md similarity=0.91`) and a safely encoded handoff filename. They no longer quote target cards, target documents, handoff text, scan excerpts or exception text. Review draft filenames replace characters outside `A-Za-z0-9._-` with `_`, and a draft name that is already taken gets a numbered suffix instead of being overwritten.
- `brigade ingest` also reads the handoff inboxes of linked git worktrees of each watched root. Worktrees come from `git worktree list` (output capped at 1 MiB and 256 records) and must share the root's common git dir. Each inbox component is opened without following links. A watched root below its checkout's top level maps to the same subdirectory in each linked checkout. A handoff whose content was already published, appended or archived in the same run is archived as a duplicate, so one handoff copied into several worktrees ingests once. A handoff skipped for a retry (for example a busy card publication lock) does not count.
- Removing a worktree through Brigade (run cleanup, `brigade runs prune-worktrees`, model trials) first moves its pending handoffs into the main checkout's inbox, deduplicated by sha256. Rescue finds inboxes from `git ls-files --others -z` (untracked files, ignored ones included, at any depth, capped at 8 MiB and 10 seconds) and delivers each to the same subdirectory of the main checkout. That subdirectory must already be a real directory reached without following links, and the destination stays open by descriptor from validation to the last write. Handoff filenames follow the same rule as ingest, so dot-prefixed handoffs such as `.pending.md` are rescued too. The destination must be the verified main checkout of the same repository. Only a handoff unmodified for 5 seconds is rescued. A newer one stays pending and keeps the worktree. Each source is claimed with an atomic no-replace rename to a private name, then copied under a temp name the ingesters ignore, fsynced, verified and published without replacing an existing file. Content that already sits in the destination counts as delivered only if ingest will read it (untracked in the inbox, or in `processed/`), and a rescued handoff is never published under a name the destination's git index tracks, even when that file was deleted. Unknown destination tracking fails the rescue. The claim is removed only after a bounded final check (size snapshot, hash and mtime, within the ingest cap and 10 seconds) still matches the delivered copy. If it changed, kept growing or the check ran out of time, the claim is renamed back to a pending handoff in the source inbox (or to a name ingest skips when it is over the ingest cap) and the worktree is kept. A handoff that appears during the rescue, a claim left by an interrupted one, or an oversize recovery file from an earlier pass also keeps the worktree, including under `force=True`, and the warning names the file. Warnings print the reason code first and shorten only the middle of a long path, never the file name. If any handoff cannot be delivered, or git tracking cannot be established, the worktree is kept and a warning names it.
- In a linked worktree, the Stop hook's handoff note names the main checkout's `.claude/memory-handoffs/`, which survives the worktree's deletion. The note text is otherwise unchanged.
