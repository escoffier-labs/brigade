- `brigade runs tasks cancel <run> <task_id>... [--reason operator|parent|budget] [--json]` records per-task cancellation intent in a durable run inbox and the owner journals it as a `task.cancel-requested` fact. A task cancelled before launch is never launched and is observed once as `cancelled` with containment `not-launched`; a sibling task keeps its own result. Unknown and terminal tasks report `unknown-task` and `already-terminal` and write nothing, and a request queued behind a live batch reports `live-termination-unavailable` because this release does not stop a running worker.
- `brigade runs tasks list` and `brigade runs tasks show` now report a `cancel` object (`requested`, `queued`, `reason`) per task.
