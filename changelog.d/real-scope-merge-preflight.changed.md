- An exact-duplicate merge of two trusted cards now applies automatically on a real scope once every merge gate rule holds: the retired card is newer by content history, no live card links to it in any case or spacing, a keeper retires at most eight cards, the keeper's text is the exact merge and search keeps every token and literal the retired card held. Preflight counts one merge pair as one changed path, treats identical claims as the proof in place of attested evidence, and ignores the alias the merge itself adds when it checks lineage. The retrieval gate is rechecked under the writer lock, so a link added after preflight still holds the apply. Several pairs, a pair beside other ops, `agent-unreviewed` cards and any earlier lineage still wait for a reviewer, and every other op class keeps the same gates.
- An automatic merge needs one writer. Both cards must carry the same writer and writer class, and that writer must be the principal and credential class applying the merge. This is read from the live heads at preflight and again under the writer lock, for every trust class. Without it any reflect principal could plant a trusted card with common claim text and later retire another principal's newer copy. A cross-writer duplicate is still proposed, holds from automatic apply with `retrieval_eval_merge_cross_writer`, stays pending in the reflect client and can be accepted by a reviewer.
- Lineage review of an exact-duplicate merge judges the keeper's whole after text, less only the one alias per retired card that the merge adds, so an alias that existed before the merge counts however it is spelled. A merge card with any lineage key (`superseded_by`, `supersedes`, `merged_from` or `aliases`) that the merge and lineage review decode differently, such as a JSON `\/` escape, goes to a reviewer, and an alias the keeper already lists is never discounted as one the merge adds. The reserved fixture scope never gets the relaxed blast cap or evidence floors, and the merge gate now also requires the keeper's before text to be its live text.
- In the preflight report, `structural_anchor_proof` now means anchoring only. A merge that clears the evidence floors on identical claims reports `structural_merge_proof` instead.
