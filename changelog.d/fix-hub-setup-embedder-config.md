- `ops/fleet-hub/bin/hub-setup.py` now writes the `[memory.embedder]` table the Rust hub parses for both hybrid paths: the full request URL and its allowlist entry, `token_file`, `shape`, `name`, `model_digest`, `dimensions`, `input_chars`, `query_prefix` and `query_prefix_version`. The per-model values come from `ops/fleet-hub/r1-models.json`, now schema 2, which also records that `qwen3-embedding:8b` passed the public-fixture half of R1. Before this, the hub refused every hybrid configuration setup wrote.
- The local GPU path gets its own embedder token file, `secrets/embed-local-token`, because the hub needs a token file for every endpoint. Both embedder token files are mode 0400. A probe that passes with a different remote token now replaces `secrets/embed-token`, and setup puts the previous file back if writing the configuration then fails, so the hub never sends one endpoint's token to another. Probe failures no longer print the HTTP library's message, which could quote the token, and a token file whose token holds whitespace or control characters is refused before any request. The remote probe now reads the model digest where the hub reads it, the `model_digest` field or the `x-model-digest` header, and refuses an endpoint that reports two different digests.
- The S31 `setup` check now starts `brigade-hub` with `--memory-config` on the configuration after `init` and after each switch direction, and requires `/ready` and the expected retrieval mode, with `degraded` for a hybrid embedder the host cannot reach. It fails when no hub binary is available. Pass `--hub-binary` and `--hub-python` to choose them.
- Hybrid retrieval under the Compose recipe is not supported yet (#2469): the Compose hub does not load setup's configuration, and the hub requires a hub-owned embedder token with mode 0400 or 0600.
