- Verify evaluation accepts a full corpus plus all retained feedback in one run, so review feedback no longer turns a full corpus into a no-go.
- `memory verify eval` reports an unanchored or unreadable corpus card as a coded failure instead of a traceback.
- The verify gate deadline scales with card runs (20 minute floor, 15 seconds per run), so a full corpus plus feedback can finish with real seats.
- The gate refuses duplicate case ids across the corpus and feedback as a no-go.
- `memory verify eval` reports corpus and harness errors with their `verify_eval_*` code (for example `verify_eval_case_invalid` for a malformed case) instead of a generic code or a traceback.
- Scheduled verify paces `verify_auto_apply` requests, tries the least recently attempted proposals first and reports a throttled attempt as `rate-limited`.
- Verify state accepts the automatic apply attempt time, so a run that attempts an application saves its state and keeps the rotation order.
- Automatic apply requests refused for authorization or an unknown proposal no longer use a rate slot.
- Verifier automatic applies keep the 24 hour card cooldown that Tier 0 applies use. A card applied or rolled back in the last day is refused with `memory_card_cooldown_active`.
- Verifier automatic applies respect the scope and operation holds that an automatic compensation installs.
