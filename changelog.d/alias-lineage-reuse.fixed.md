- The memory hub no longer links or collapses a new card under a keeper because the keeper's `aliases` names an id the card reused. An `aliases` lineage edge forms only when the named card's current incarnation began before the keeper revision that wrote the alias.
- A merge no longer copies an alias from the retired card to the keeper when a card now holds that id and began after the alias was first written. A keeper whose id was retired and reused dates its aliases from the new card. An alias with no known date never forms an edge.
- Every lineage key now uses the same reuse dating as `aliases`: `supersedes`, `merged_from` and `superseded_by` form an edge only when the named card began before the owner first wrote the name, judged per key. An id in both `aliases` and `supersedes` no longer keeps an undated edge, and a `superseded_by` naming a reused id no longer collapses the owner under the new card. A reviewed accept of a chained merge is refused as `stale` with `inherited_alias_reused` when an inherited alias id was taken after submit. Dating reads at most 256 histories per publication through a reverse index from named id to owners, and a builder that has been dated stays dated. Scorer version is now `lineage-source-v6`.
