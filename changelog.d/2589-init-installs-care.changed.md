- `brigade init` and `brigade operator quickstart` now turn on extras and install the default care schedule, the same as running `brigade extras on` and `brigade care install --target <target>` after setup, so the weekly outcome ratchet runs with no further step. Pass `--no-care` to skip both, and the skip message names both commands to run later. The care step never changes the exit code and reports one status: `installed`, `installed` with a `not_started` list when no systemd user manager is reachable (the warning names the `systemctl --user` commands), `unsupported` on Windows where care install does not write the scheduler yet, `skipped`, or `failed` with the reason. A repeat init leaves an installed schedule alone and `--dry-run` lists both steps without running them. New `brigade init --json` prints one result object with the extras and care statuses (#2589).
