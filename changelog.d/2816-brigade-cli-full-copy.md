- Publish `brigade-cli` through 0.33 as a full build of the same source under the old name, not a package that depends on `brigadestack`. It has the same version, dependencies, extras and `brigade` package files as `brigadestack`, and declares the `brigade`, `brigade-cli` and `brigade-hook` commands. `pipx upgrade brigade-cli` stays an ordinary in-place upgrade; the thin package broke it, because pip wrote the new `brigadestack` files and then the old `brigade-cli` uninstall deleted them, which left every command failing with `ImportError: cannot import name 'process_main'` (#2816).
- `publish.yml` builds the `brigade-cli` sdist and wheel from a temporary copy of the tree that `scripts/stamp_brigade_cli.py` renames, and never edits the checkout. `distribution/brigade-cli/pypi/pyproject.toml` is removed, and `scripts/version_sync.py` no longer tracks it.
- The PyPI publish job runs `scripts/check_cli_upgrade.py` first: in a fresh venv it installs the newest older stable `brigade-cli` from PyPI, upgrades it to the built wheel, and requires `brigade --version` to report the new version and `brigade-hook --help` to run, so a broken in-place upgrade cannot be uploaded.
