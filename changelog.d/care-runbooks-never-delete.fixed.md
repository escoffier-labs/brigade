- `brigade care install` no longer deletes or overwrites runbooks. A workspace missing one newly shipped memory-care runbook used to have the whole `.brigade/memory-care/runbooks` directory replaced with the templates, deleting operator runbooks and customized shipped ones. Every care runbook writer (shipped memory-care, daily-observability, memory-closeout, run-patrol) now keeps any existing regular file, refuses a symlink, directory or other non-regular entry at a runbook name (exit 2, path named), refuses a symlinked or outside-the-target `.brigade`, `memory-care` or `runbooks` path, stages in a private temp directory, and validates and pins every runbook before publishing any. `care install` publishes all of them as one batch, so a bad destination for any runbook leaves every runbook unwritten, and `--dry-run` writes nothing and prints the runbooks it would write. An OS failure while publishing exits 2 naming the file and the ones already published instead of raising. `brigade memory care init --with-runbooks` adds only missing shipped runbooks; with `--force` it also refreshes shipped files that differ from the templates, printing each one it replaced and copying it to `<name>.bak-<UTC timestamp>` first. A shipped file that differs only in its `pins` block (after a `brigade` upgrade) is re-pinned in place with no backup and reported as `re-pinned`.
