- `brigade care install` no longer deletes or overwrites runbooks. A workspace missing one newly shipped memory-care runbook used to have the whole `.brigade/memory-care/runbooks` directory replaced with the templates, deleting operator runbooks and customized shipped ones. Every care runbook writer (shipped memory-care, daily-observability, memory-closeout, run-patrol) now keeps any existing regular file, refuses a symlink, directory or other non-regular entry at a runbook name (exit 2, path named), refuses a symlinked or outside-the-target `.brigade`, `memory-care` or `runbooks` path, stages in a private temp directory, and validates and pins every runbook before publishing any. An OS failure while publishing exits 2 naming the file and the ones already published instead of raising. `brigade memory care init --with-runbooks` still refreshes the shipped files, now printing each one it replaced and copying a customized one to `<name>.bak-<UTC timestamp>` first.
