- `brigade work dispatch` no longer trusts a receipt's size, `mtime_ns`, and inode alone to decide it is unchanged. A receipt written inside a two-second safety window is re-verified by content digest, so an atomic replace that recycles the inode with the same byte length in the same filesystem timestamp tick cannot leave a stale active or completed state in the exclusion index (#1946).
- The exclusion index stores a content digest per receipt and rebuilds when the digest no longer matches, which keeps breaker counts and exclusions identical to a full scan of the receipts (#1946).
