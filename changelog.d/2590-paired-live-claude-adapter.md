- Add a live paired-skill adapter over the Claude Code CLI (#2590): `brigade model trial paired-live` launches a fresh `claude -p` per arm with one exclusive MCP server (`brigade model trial paired-mcp`) exposing only the five paired tools, gates on the stream's `system/init` event before grading, and treats the server-side trace as authoritative. Live evidence has its own adapter id and schema (`model_executed: true`, `promotion_eligible: false`); `brigade.offline-replay.v1` is unchanged and resume refuses any identity change. Authentication is the subscription OAuth token only. The init gate also pins `cwd`, `agents`, additional directories and `permissionMode`, passes `--settings` with every builtin plugin disabled and requires no plugins, inspects `tool_use`, `server_tool_use` and `mcp_tool_use` blocks with strict id checks, refuses a temp location with `CLAUDE.md` or `AGENTS.md` in an ancestor, and redacts the OAuth token from saved artifacts. Docs include an operator runbook for the first live `passing-verify` pair. The adapter resolves, hashes and holds the Claude executable and runs the version probe and every arm from that held file (Linux `fexecve`; other platforms refuse a live run), recording the hash in the cell identity. Child stdout and stderr are redacted in memory before any byte is written, the MCP server config blanks the token, resume needs the reviewed digest via `--resume-digest` (without it earlier evidence is moved aside and every cell runs fresh), and package, `SKILL.md`, stream line, stderr, trace and receipt sizes are capped before they are buffered.
- A paired grade now appends the last stderr line of a failed `brief` or `capture` Brigade subprocess to its reason (one line, 200 characters at most), and the live adapter tests pass the real `PATH` on Windows so `git` is reachable.
- Live paired trials now refuse to start when a passed-through proxy variable carries `user:password` (the message names the variable, never the value), blank every proxy variable in the MCP server config, cap the evidence peek in `paired_validate` at `MAX_EVIDENCE_BYTES`, and bound the Claude version probe to 4096 bytes with a kill on overflow or timeout.
- Live paired runs now refuse any proxy value containing `@` (raw or percent-decoded), which closes the `http:/user:pw@host` and `http:////user:pw@host` forms Node reads as authenticated URLs. Process cleanup never signals a pid it may have reaped (an unreaped child only, serialized with the reaping wait in the arm and the version probe), and on POSIX the arm waits for the CLI to exit without reaping it (`waitid` with `WNOWAIT`), kills the whole process group, then reaps, so an MCP server that outlived the CLI is gone before the arm directory is removed, Windows no longer shells out to `taskkill` and relies on the MCP server exiting with its CLI plus a bounded retry (up to about 7 s) when removing the arm directory, and on Windows that removal never chmods a symlink, a reparse point or a path outside the arm directory. On POSIX the arm directory is removed with a plain `shutil.rmtree`: no chmod repair at all, a read-only file goes without one, and a failure is raised.
