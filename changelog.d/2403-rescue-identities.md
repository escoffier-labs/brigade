- Hold a worktree's Git admin directory and its `worktrees` parent open from the moment rescue verifies them, take identities from those descriptors rather than path lookups, prove the admin `gitdir` entry names the worktree's own `.git` file by identity, and run the tracked-handoff query pinned to the held work tree and admin directory, so a rename that swaps a replacement anywhere in that window cannot redirect rescue or removal. Removal renames the rescued tree to a private name through its held parent, opens that entry no-follow, compares its identity with the held one, deletes contents only through that descriptor, and drops the name with `rmdir`, so an exchanged tree survives. The worktree's registration is removed through the held admin descriptor and its `worktrees` parent instead of a repository-wide `git worktree prune` or any path-based `git worktree remove`, a locked worktree is kept unless removal is forced, and a restore that cannot use a no-replace rename reports the private location. Windows keeps the pre-PR removal path unchanged, and platforms without `/proc/self/fd` keep the worktree with `worktree-unverified` for manual cleanup.
