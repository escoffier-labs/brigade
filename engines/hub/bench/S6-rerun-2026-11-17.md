# S6a heartbeat rerun, 2026-11-17

This reruns the S6a heartbeat matrix from [S6.md](S6.md) at commit
`e38826ea66c727b367594d9d0a9ffd7f4945fd74` on 2026-11-17. Both targets used
`FULL` synchronous commits and flushed every write. Each run used a fresh
database with no events, one heartbeat node, one event per request, four
client processes, closed-loop requests with 1 ns think time, and connections
that closed after each request. The mixed setting ran claims and Python
preference writes alongside heartbeats.

Each run measured 30 seconds after a 5-second warmup. Each target ran twice
per client count and setting except for `confirm-16` and `wal-probe`, which
ran once per target. Client and server processes were pinned to disjoint
CPU sets. The reference setting used no cgroup CPU or memory cap, and the
constrained settings used the recorded cgroup limits.

The harness summary JSON is the source of every number in the results tables.
[Per-run summary JSON](S6-rerun-2026-11-17.json) retains the full numeric
precision and the setting summary's mixed claim measurements. Latency
percentiles include failed attempts. Errors include Rust busy replies. The
harness records no separate busy count, so a Rust row with non-transport
errors shows `unreported` in that column. The column applies only to Rust.

The temp-dir (A) runs and the real-disk (B) runs are not comparable with each other.

## Reproduce

Use the matching release binary and follow the
[heartbeat invocation in the harness README](README.md#s6-native-heartbeat-comparison)
from the repository root. Set `HUB_BINARY` to the release binary,
`OUT_DIR` to a fresh results directory, `LOOP_TMPDIR` to a writable
loop-backed temp directory, and `REAL_DISK_TMPDIR` to a writable real-disk
temp directory. Set `REFERENCE_CPUS`, `CONSTRAINED_CPUS`, and `CLIENT_CPUS`
to the benchmark allocations on the test machine, with client CPUs outside
both server sets. Run the following inside the executable script passed
to Brigade.

```bash
run_heartbeat() {
  local server_cpus="$1" output="$2"
  shift 2
  python engines/hub/bench/heartbeat.py --binary "$HUB_BINARY" \
    --output "$OUT_DIR/$output" --server-cpus "$server_cpus" \
    --client-cpus "$CLIENT_CPUS" --seconds 30 --warmup 5 \
    --nodes 1 --processes 4 --batch-events 1 --connection close "$@"
}

# Setup A
TMPDIR="$LOOP_TMPDIR" run_heartbeat "$REFERENCE_CPUS" reference \
  --clients 16 64 256 --repetitions 2
TMPDIR="$LOOP_TMPDIR" run_heartbeat "$CONSTRAINED_CPUS" constrained \
  --allotment 1cpu-512m --clients 32 --repetitions 2
TMPDIR="$LOOP_TMPDIR" run_heartbeat "$REFERENCE_CPUS" mixed \
  --clients 64 --mixed --repetitions 2
TMPDIR="$LOOP_TMPDIR" run_heartbeat "$REFERENCE_CPUS" confirm-16 \
  --clients 16 --repetitions 1

# Setup B
TMPDIR="$REAL_DISK_TMPDIR" run_heartbeat "$REFERENCE_CPUS" ref16 \
  --clients 16 --repetitions 2
TMPDIR="$REAL_DISK_TMPDIR" run_heartbeat "$CONSTRAINED_CPUS" con32 \
  --allotment 1cpu-512m --clients 32 --repetitions 2
# Repeat of con32; the name records the load average (about 1.05) logged before it started.
TMPDIR="$REAL_DISK_TMPDIR" run_heartbeat "$CONSTRAINED_CPUS" con32-load105 \
  --allotment 1cpu-512m --clients 32 --repetitions 2
# Single pair run while sampling hub WAL size and checkpoint counters each second (sampler not included).
TMPDIR="$REAL_DISK_TMPDIR" run_heartbeat "$REFERENCE_CPUS" wal-probe \
  --clients 16 --repetitions 1
```
